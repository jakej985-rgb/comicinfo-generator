# Metadata Resolution — ComicInfo Generator

## Purpose

Describes the **actual, implemented** two-phase metadata resolution pipeline.

---

## Responsibilities

`pipeline/resolver.py → MetadataResolver`

1. **Phase 1 — Identity Resolution** (`resolve_identity`): determines *what* the comic is.
2. **Phase 2 — Metadata Retrieval** (`retrieve_metadata`): fetches full details for a resolved identity.

These two phases are strictly separated. No metadata retrieval occurs before identity is confirmed.

---

## Inputs

- `file_path: str` — path to `.cbz` or `.cbr` archive
- `url_override: str` (optional) — direct Comic Vine / GCD URL to bypass search
- `force_overwrite: bool` — whether to ignore existing embedded `ComicInfo.xml`

---

## Outputs

`(Comic | None, provider_name: str)`

---

## Identity Resolution Priority Chain

```text
1. Direct URL override (user-supplied CV/GCD URL)
   ↓
2. Existing embedded ComicInfo.xml (unless overwrite=True)
   ↓
3. Filename / directory parsing (pipeline/filename_parser.py)
   ↓
4. Kapowarr search (if online)
   ↓
5. Comic Vine search
   ↓
6. GCD search
   ↓
All candidates → scored by pipeline/scoring.py
             → evaluated by pipeline/confidence.py
             → ConfidenceDecision returned
```

---

## Confidence Levels

Defined in `pipeline/confidence.py`:

| Level | Score | Action |
|---|---|---|
| `AUTO_ACCEPT` | ≥ 90 | Embed immediately |
| `ACCEPT_WITH_WARNING` | 70–89 | Embed with warning logged |
| `MANUAL_REVIEW` | 50–69 | Add to review queue, generate report |
| `UNRESOLVED` | < 50 | Skip, log, record state |

Reports for `MANUAL_REVIEW` candidates are generated by `pipeline/review.py`.

---

## Collected Edition Merge Policy

When multiple issues are merged into a TPB/collected edition:

| Field | Priority Source |
|---|---|
| `title` | collection_override > generated range ("Series #1-6") |
| `publisher` | Kapowarr identity > collection_override > first issue |
| `year` | collection_override year > earliest issue year |
| `summary` | collection_override > per-issue with `--- Issue #N ---` headers |
| `characters` | union + deduplicate (order-preserving) |
| `writers/…` | union + deduplicate per role |
| `story_arcs` | union + deduplicate |
| `web` | collection_override URL > comma-joined issue URLs |
| `provider_id` | collection_override ID > first resolved issue ID |

`MergeResult.provenance` records which source won each field.

---

## Pre-Merge Validation (Phase 26)

`pipeline/collection.py → validate_collection()` enforces:

| Check | Result |
|---|---|
| Different series names | REJECT |
| Different provider `volume_id` | REJECT |
| Same base number with variant suffix (#1 + #1A) | WARN |
| Publisher mismatch | WARN |
| Sequential issues, same series/volume | ACCEPT |

---

## Issue Ordering

`pipeline/issue_order.py` normalises all issue numbers to `IssueOrder(numeric_value, letter_suffix)`.

- Never uses `int()` on issue strings.
- Named types (Annual, Special, TPB) sort after regular issues.
- `sort_issues(["0.5", "0", "1", "Annual"])` → `["0", "0.5", "1", "Annual"]`

---

## Invariants

- Identity resolution happens before any archive write.
- `AUTO_ACCEPT` does not require human confirmation.
- `MANUAL_REVIEW` never auto-embeds; it always waits for human approval.
- A file with `confidence < 50` is never embedded.

---

## Failure Modes

| Failure | Outcome |
|---|---|
| All providers offline | Returns `(None, "None")` — no embed |
| Filename unparseable | Falls back to directory name |
| Confidence < 50 | `UNRESOLVED` — state recorded, file untouched |
| Provider returns duplicate candidates | Scored independently, highest score wins |

---

## Do-Not-Do Rules

- Do not accept the first provider search result automatically.
- Do not bypass `MetadataResolver` to call providers directly.
- Do not embed without first producing a `ConfidenceDecision`.
- Do not use `int(issue_number)` anywhere — use `parse_issue_order`.
- Do not add provider-specific fields to `ComicIdentity` or `Comic`.
